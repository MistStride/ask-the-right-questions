# 开发路线图 · ROADMAP

> 本文件是《学会提问》交互式批判性思维游戏的**开发总纲**，之后每次开发都照本文件推进：**一次只做一个阶段，做完先跑起来看效果（验收标准），再进下一阶段**。
>
> 顶层设计详见总纲文档（`D:\下载\学会提问_完整技术设计方案.md` / `学会提问_游戏化设计方案.md`），本文件是落地执行清单。

## 工程铁律（每次开发都遵守）

1. **一次只做一个阶段**：做完跑起来玩一遍，验收通过再继续，禁止一次性堆多个阶段。
2. **内容与引擎分离**：加新章节只碰 `src/content/levels/` 的 JSON，引擎代码不改。
3. **语义锚点而非字符偏移**：找"原文片段"，中英文各写各的，互不干扰。
4. **判定逻辑与文案解耦**：逻辑文件不含语言，i18n 文件不含判定。
5. **JSON 靠 Zod 校验**：字段写错在 dev/build 期立即报错。
6. **新引擎 = 复制 `engines/xray/` 结构**：类型 + Schema + 组件 + 分发 case，四件套齐活。
7. **验收标准 = 界面里能看到**：做完刷新浏览器，能看到效果才算完成。
